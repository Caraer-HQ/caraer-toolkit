# Vacancy Object Template

Status: Canonical primary object; recruitment record.

## Purpose

`vacancy` represents an independently identifiable role or assignment to
which a Candidate can apply.

## Traits

### Enabled by default

- **Table** — vacancy list.
- **Page** — vacancy detail pages and publishing. The Page trait supplies
  `page_v2_title`; no separate `title` or `vacancy_name` property is defined.

### Optional by workspace configuration

- **Analytics** — recruitment funnel reporting.
- **Task** — vacancy follow-up and hiring work.

### Not enabled by default

- **Candidate** is related through `applies_to`, not an extension of Vacancy.

## Property definition

Each property definition records the fields needed for MCP creation and UI
behaviour:

| Field | Purpose |
| --- | --- |
| `name` | Stable internal property key. |
| `label_nl` | Dutch UI label. |
| `label_en` | English UI label. |
| `type` | Stored data type. |
| `format` | Supported input/display format. |
| `group` | UI property group. |
| `options` | Select options, where applicable. |
| `settings` | Property settings shown in the Object UI. |
| `icon` | UI icon, where applicable. |
| `notes` | Ownership, source, behaviour, or implementation notes. |

Supported types and formats follow the Caraer MCP lists. The Object UI's
Settings panel maps to MCP as follows:

| UI setting | MCP field | Values |
| --- | --- | --- |
| Required | `rules` | `required` |
| Required when | `requiredFilter` | Filter definition |
| Unique | `rules` | `unique` |
| Hidden | `hidden` | `true` / `false` |
| Non-public | `nonPublic` | `true` / `false` |
| Indexed | `indexed` | `true` / `false` |
| Lifecycle | `lifecycleActive` | `true` / `false` |
| Sensitive | `sensitive` | `true` / `false` |
| Public for webpages | `webpagePublic` | `true` / `false` |

Thus `Unique` is a UI setting backed by the MCP `rules` array. A property can
have both `required` and `unique`, for example `rules: ["required", "unique"]`.

For exact MCP parity, an implementation may additionally specify `rules`,
`requiredFilter`, `description`, `editable`, `immutable`, `indexed`,
`webpagePublic`, and `sensitive`. These are implementation metadata rather
than part of the normal content-property proposal and should remain unset
unless the workspace has a concrete requirement for them.

## Relations

Candidate, organisation, owner, and campaign relations should be modelled as
Relations when their records are independently identifiable. Candidate
applications should use `applies_to`; they should not be stored as Vacancy
properties.
